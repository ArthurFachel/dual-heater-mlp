# dual-heater-mlp

Research code for neuron-level plasticity mechanisms in continual learning
(DualHeat / SlowHeat). This is a *research* repository: results are evidence,
and overclaiming is the main failure mode. Read `README.md` §"Safe claims"
before writing anything that resembles a result.

## Running things

Default to CPU and pin threads. These three variables are the house style for
any local run, and they keep a stray job from saturating the machine:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' \
PYTHONPATH=src:. python -m experiments.synthetic_cl --help
```

`PYTHONPATH=src:.` is required for the `experiments.*` module entry points.

## Verification

Tests (this is what CI runs — match it exactly):

```bash
CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1 \
PYTHONPATH=src:. pytest -q -p no:cacheprovider
```

Lint (CI gate, no project config — plain ruff defaults):

```bash
ruff check .
```

CI runs both on Python 3.10 and 3.13 (`.github/workflows/ci.yml`). Code must
stay compatible with 3.10 even though the local venv is 3.12 — no `match`
guard-only syntax from 3.11+, no `typing` features newer than 3.10.

Preview a full protocol without training anything:

```bash
python run_all_tests.py --num-seeds 10 --dry-run
```

## Ask before doing

These are expensive or destructive. Ask first, every time:

- GPU training runs of any size.
- Dataset downloads (prefer `--no-download` when data is already local).
- Installing or upgrading dependencies.
- Anything that writes under `results/` for a *reported* run.

Lightweight CPU tests and dry runs are pre-approved — just hide the GPU and
pin threads as shown above.

## Scientific discipline

This matters more than the code style.

- **Never strengthen a claim the evidence does not support.** `README.md` keeps
  an explicit "Safe claims" / "Not supported" split. A result confirmed on
  Split-MNIST against plain Replay is exactly that — not superiority over EWC,
  DER++ or ER-ACE, and not a general reduction of forgetting.
- **Exploratory is not confirmatory.** Label it. Ten-seed Split-CIFAR
  aggregates under `results/` are exploratory and were not analysed in the
  docs; do not quote them as findings.
- **Provenance is part of the result.** Runners write `environment.json`,
  `run_identity.json` and `data_identity.json`. A run recorded with a dirty Git
  tree cannot establish bit-for-bit reproduction — say so when reporting it.
- **A runner bug invalidates its runs.** Precedent: the 2026-09-02 audit found
  epoch-end eval not restoring train mode, which silently broke SlowHeat
  importance accumulation. Every confirmation executed before the fix was
  discarded. If you find a bug in a runner, assume affected results are invalid
  until re-run.
- Protocols are preregistered in `goals/protocol_*.md`. Read the protocol
  before touching its runner, and do not change seeds, hyperparameters or the
  declared endpoint of a frozen protocol.

## Layout

```text
src/dual_heater/   mechanisms: slow_heat, fast_heat, dual_heat, optim, metrics,
                   transformer, bert, resnet, lora, plasticity, ewc, state
experiments/       runners and benchmark entry points
scripts/           launch_*.sh and run_*.py for specific protocols
tests/             pytest suite
docs/              method contracts, protocols, results records
goals/             preregistered protocols and roadmap (Portuguese)
article/           manuscript draft
results/           gitignored; old trees kept as historical evidence
```

Documentation entry points worth reading before changing a mechanism:
`docs/mechanisms/functional_slowheat.md` (method contract),
`docs/mechanisms/optimizer_semantics.md` (masking and checkpoint semantics),
`docs/protocols/confirmatory_protocol.md` (frozen confirmation).

## Conventions

- Commits: conventional-commit type in English, subject in Portuguese.
  Example: `feat: agregador do L2 que julga C1-C5, com 6 mutacoes mortas`.
- Docs and code comments are written in English; `goals/` is in Portuguese.
- Do not commit anything under `results/`, `.venv/`, `.hf-cache/` or `data/`.
- Never commit unrelated working-tree changes you did not author.
